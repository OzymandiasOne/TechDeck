# Authoring a TechDeck plugin

A plugin is a folder `plugins/<id>/` containing exactly **`plugin.json`** (metadata) and
**`run.py`** (code). At runtime it loads from `%LOCALAPPDATA%\TechDeck\plugins\<id>\`.

> The terse Hard Rules in `AGENTS.md` still apply and are always in force; this skill is
> the procedural detail + rationale + code for building plugins. When you finish, follow
> the **Documentation Update Protocol** in AGENTS.md (add the plugin to the Installed
> Plugins tables in AGENTS.md + README, append a row to the tracking workbook).

## Fast start

1. Copy the scaffold in this skill's `templates/` to `plugins/<id>/` and rename.
2. Fill in `plugin.json` (id MUST equal the folder name — single underscores).
3. Implement `run(params, progress_callback, cancel_event)` in `run.py`.
4. **Dev-test**: copy the folder to `%LOCALAPPDATA%\TechDeck\plugins\<id>\` (the app loads
   from there, even in dev) OR run the `run.py` headless harness (below).
5. Launch with `python -m techdeck`, run the plugin's tile, verify console output.
6. Sync docs (see AGENTS.md Documentation Update Protocol).

## plugin.json schema

```json
{
  "id": "my_plugin",
  "name": "My Plugin",
  "description": "Short description shown in the UI",
  "version": "1.0.0",
  "author": "Anthony Sieben",
  "family": "911",
  "icon": "icon.png",
  "requires_admin": false,
  "requires_main_thread": false,
  "timeout": 300,
  "settings": {
    "fields": [
      {
        "key": "base_path",
        "type": "directory",
        "label": "Base Directory",
        "description": "...",
        "placeholder": "C:\\...",
        "required": true,
        "default": ""
      }
    ]
  }
}
```

Field types: `directory`, `file`, `string`, `number`, `boolean`.

- **`id`** — MUST exactly match the folder name, single underscore. A double underscore
  (`911__setup`) makes the loader skip the folder. (Failure mode: "plugin not discovered".)
  **Naming convention (gate check E9):** id = snake_case slug of the Library display
  name, family-prefixed — 902/911/922/QA names start with their family ("911 Setup"→
  `911_setup`, "QA Gemba Analyzer"→`qa_gemba_analyzer`), Games ids get a `game_`
  prefix ("ASA: The Video Game"→`game_asa_the_video_game`), and family-less
  ("other") plugins are just the slug. Renaming an existing id ALSO needs a
  `_PLUGIN_ID_RENAMES` entry in `techdeck/core/settings.py` (migrates profile tiles,
  plugin settings, run stats, and Emporium unlocks) + an `[InstallDelete]` line in
  `TechDeck-Setup.iss` (removes the old folder on update so tiles don't duplicate).
- **`family`** — `"902"`, `"911"`, `"922"`, `"QA"`, `"Games"`, or `"other"`. Drives (a) the
  Library page's "Sort: By Family" mode and (b) family-aware shared state in
  `sdk.request_batch_number` so same-family plugins in a multi-run share one
  batch-number prompt. If absent, `plugin_loader._infer_family_from_id` falls back to
  a prefix check (`902_*`→`902`, `911_*`→`911`, `922_*`→`922`, `qa_*`→`QA`, `game_*`→`Games`, else
  `other`) — but set it explicitly anyway.
- **`icon`** — optional, the tile icon on the Home/Library grids. Rendering +
  resolution live in `techdeck/ui/plugin_icon.py` → `plugin_icon_pixmap`, order:
  (1) the **custom pixel-art set** — `PLUGIN_ICON_KEYS` maps `plugin_id → subject key`, and
  the PNG is theme-matched (`assets/icons/tile icons/TechDeck pixel/<theme>/<key>.png`,
  generated by `tools/generate_tile_icons.py`). For a NEW shipped plugin: add a subject
  drawing fn + `ICONS` entry in the generator, re-run it, and add a `plugin_id: "key"` entry
  to `PLUGIN_ICON_KEYS` (key on the **runtime id**, not the folder); (2) an image file in
  the plugin folder named by this `icon` field (`icon.png` next to `run.py`; PNG preferred);
  (3) an emoji string (legacy); (4) a **family-colored monogram** fallback so a missing icon
  never looks broken.
- **`requires_main_thread: true`** — required for GUI plugins; the executor runs these on
  the main Qt thread via `QTimer.singleShot`.
- **`timeout`** — per-plugin **idle** timeout override (s). Default 1800s of inactivity
  (`DEFAULT_PLUGIN_TIMEOUT`). The watchdog is inactivity-based: a long job is safe as long
  as it keeps logging or reporting progress.

## run.py interface

Every plugin implements this exact signature:

```python
def run(params: dict, progress_callback: callable, cancel_event: threading.Event):
    log = params.get('log', print)
    settings = params.get('settings', {})
    console = params.get('console')      # ConsoleWidget reference
    log("Starting...")
    progress_callback(25)
    if cancel_event.is_set():
        return
    # do work...
    progress_callback(100)
```

- `params['log']` — thread-safe logging to the console.
- `params['settings']` — dict of settings values from the plugin.json fields.
- `params['console']` — ConsoleWidget; `console.request_input(prompt)` blocks for input.
- `params['plugin_id']` / `params['plugin_family']` ("902"/"911"/"922"/"QA"/"Games"/"other") — injected.
- `params['shared_state']` — per-run, per-family scratch dict. Use SDK helpers, not direct.
- `params['on_input_idle']` — internal watchdog callback for auto-pause; never call it.
- `params['on_success']` — the success chime. The shell suppresses its auto chime for
  `requires_main_thread` plugins (a GUI plugin's run() returns as soon as the window is
  up, which would chime too early), so **every GUI plugin MUST call this itself at its
  meaningful success moment** — files written, PDF exported, entry logged — or its runs
  finish silently (bit SSPO Invoicing Prep, DXF Quoting, and Gemba Analyzer; fixed
  post-0.8.6). Pattern: `on_success = params.get("on_success")` →
  `if callable(on_success): on_success()`. Worker-thread plugins ignore it (auto chime).
- `progress_callback(int)` 0–100. `cancel_event` — check `.is_set()` in long loops.

## Console input for runtime prompts

**Always prefer the SDK helpers over raw `console.request_input`** — they handle
family-shared caching and the standalone-CLI fallback.

```python
from techdeck.core import plugin_sdk as sdk

batch = sdk.request_batch_number(params, "Enter batch number:")  # cached per family
line  = sdk.request_text(params, "Which line, 911 or 922?")      # never cached
folder = sdk.request_directory(params, "Select the batch folder")  # native dialog
```

For a per-run **folder** input (a batch folder, a ROOT of orders), use
`sdk.request_directory(params, title, start_dir="")` — it opens the native
pick-a-folder dialog on the GUI thread (console `request_directory`, same blocking
contract as `request_selection`) and returns the path or None on cancel; headless it
falls back to a pasted-path prompt. Don't make users paste paths through
`request_text`.

For a pick-which-items dialog, `console.request_selection(items, done_items,
**kwargs)` (guard with `hasattr` + provide a headless fallback). kwargs reach
`SelectionDialog`: window_title/header/root_label/noun/run_button_text/… plus
`disabled_items=`/`disabled_label=` for GREYED-OUT non-selectable rows — use these to
advertise a planned-but-not-built step (first used by Baked Beans Wild Ride's "Run NC
Style Baked Beans spreadsheet" teaser). Disabled rows never count or return.

`console.append_link(text, target_path, prefix="", at_run_end=False)` (thread-safe;
guard with `hasattr`) appends a CLICKABLE console line that opens `target_path` with
its default app — `prefix` renders as a bold egg-purple channel tag, `text` as
underlined body text. Pass `at_run_end=True` for a finale line: it's deferred until
after the shell's ✅-completed/ticket messages so it prints LAST (from run() it would
otherwise race ahead of them).
**Version tolerance:** when a console method gains a NEW keyword arg, wrap the call in
`try/except TypeError` with a no-kwarg fallback — a still-running/older TechDeck has
the old signature and the kwarg call raises at runtime (bit Wild Ride's finale: the
run "failed" after the output was already written).

**Hard Rule (don't break):** a batch-number prompt MUST use `sdk.request_batch_number`;
any other prompt MUST use `sdk.request_text`. `request_batch_number` caches its answer in
the per-family shared state and reuses it for same-family plugins in the same multi-run.
Two failure modes, both real:
- Prompting for a batch via raw `console.request_input`/`input` skips the cache, so the
  next same-family plugin re-prompts instead of reusing it (bit FormingFinder→Kitting,
  fixed v0.8.6.3).
- Using `request_batch_number` for an unrelated prompt poisons the cache — the next real
  batch prompt silently picks up the wrong value (bit `batch_auditor`: a "which line?"
  prompt poisoned the batch cache).

`check_ship_readiness.py` check E8 fails the build on the first failure mode (a "batch
number" prompt routed through raw input/request_input/get_console_input).

`InputAborted` (from `console.py`) is raised when a prompt is interrupted (Clear/`/clear`,
`/pause`, or watchdog auto-pause). Just let it propagate — the executor maps it to
CANCELLED/PAUSED. Console games that block on input must pass `owner='game'`.

## GUI plugins (`requires_main_thread: true`)

```python
from techdeck.core.plugin_window import PluginWindow

_window = None  # module-level — prevents garbage collection

def run(params, progress_callback, cancel_event):
    global _window
    _window = PluginWindow("my_plugin", "My Plugin Title")
    # build UI, add widgets to _window._main_layout
    _window.show()
```

**Hard Rules:** (1) store plugin windows in **module-level** variables — in local scope Qt
garbage-collects them immediately and the window vanishes. (2) Only create QWidgets on the
main Qt thread — set `requires_main_thread: true`; creating widgets from a worker thread
causes crashes and `QBasicTimer` errors.

Dashboards: a plugin renders charts by passing a plain-data spec to
`console.show_dashboard(spec)` (thread-safe, marshals to the GUI thread). Spec format +
rendering live in `techdeck/ui/widgets/dashboard.py`. Charts need `PySide6.QtCharts` in
hiddenimports. `batch_auditor` is the reference consumer.

## Plugin SDK — `techdeck/core/plugin_sdk.py`

Single source of truth for cross-plugin logic. **Prefer these over re-implementing
path/Excel/PDF logic.** Import bootstrap (works for CLI testing too):

```python
try:
    from techdeck.core import plugin_sdk as sdk
except ModuleNotFoundError:
    import sys, pathlib
    sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[2]))
    from techdeck.core import plugin_sdk as sdk
```

Provides:
- **OneDrive roots:** `resolve_922_root`, `resolve_911_qtdr_root`, `resolve_forecast_dir`,
  `pilot_program_roots`, `resolve_under_pilot_program`. (Tries the two known OneDrive
  folder names, then any saved Settings > Apps directory override's parent — one
  manually-set app directory heals every other consumer, incl. the feedback writer —
  then DISCOVERS the library by glob: tenant-name variants, "Add shortcut to My files"
  layouts, relocated OneDrive. A plugin never makes the user type a path. Fresh installs
  failed on non-canonical layouts until v0.8.6.1; never hand-roll root lookup.)
- **Batch parsing:** `parse_922_batch` ("Batch 403"/"PO #403"/"403"→`403`),
  `normalize_911_batch` (trim+upper, alphanumeric like `V060`).
- **Batch-folder location:** `find_922_batch_path` (incl. `1 - Completed` archive),
  `find_911_batch_folder`.
- **Excel header lookups:** `find_header_col`, `header_map`, `find_header_row(ws,
  required, max_scan)`. Always look columns up by NAME (Hard Rules 1–2).
- **Tube materials:** `STANDARD/OVERSIZED/ALL_TUBE_MATERIALS`, `tube_class(serial)`
  (canonical sets; `922_lst_organizer` imports them).
- **PO reader:** `read_qf_qu_09(po_path)`.
- **Console input:** `request_batch_number`, `request_text`, `request_directory`
  (native folder picker; see above).
- **Blocking warning popup:** `show_warning(params, title, text)` — modal QMessageBox
  on the GUI thread (console `show_warning`, same worker-thread contract as
  `request_directory`); headless or on an older TechDeck it logs instead. Use for
  problems the user must acknowledge (skipped inputs, unresolved references) — a
  console log line scrolls past unseen. First used by 911 LST Organizer.
- **PDF:** `merge_pdfs(pdfs, out)`, `save_pdf_atomic(doc, dest)`.
- **OneDrive cloud placeholders (Hard Rule 13):** a dehydrated Files-On-Demand file
  exists but its content read raises `OSError [Errno 22]` — or, for xlsx/zip reads,
  `zipfile.BadZipFile: File is not a zip file` (zipfile swallows the OSError while
  seeking the central directory and re-raises it as BadZipFile). Use
  `load_workbook_resilient(path, log=..., **kw)` for ANY workbook under the OneDrive
  tree, and `ensure_local(path, log=...)` immediately before any other content read —
  `fitz.open`, `PdfReader`, `pd.read_excel`, or a `shutil.copy` SOURCE. Both
  force-download with retries or raise a user-actionable error. Lower-level:
  `is_cloud_placeholder(path)`, `hydrate_cloud_file(path, log=...)`. Every plugin's
  read sites were converted in the post-0.8.6.1 sweep — keep new reads converted.
  **A different failure, same guardrail: a file the user has OPEN in Excel/Acrobat
  raises `PermissionError [Errno 13]` (content IS local; another process holds a
  deny-share lock — retry/copy can't fix it).** The resilient loaders map it to
  `sdk.locked_file_error` ("… is open in another program … close it and run again")
  so plugins never crash with a raw traceback (bit 902 DXF Prep on the pricing
  `.xlsm`, v0.8.6.8). For pandas reads use `read_excel_resilient(path, log=..., **kw)`
  or `open_excel_resilient(path, log=...)` (→ a `pd.ExcelFile`); to stage a live
  workbook to a temp copy use `copy_resilient(src, dest, log)` — it hydrates the
  source AND surfaces the locked-file message from the copy step.

`request_batch_number` resets at the start of every fresh `_run_selected_plugins` and after
a successful shelf load.

## Plugin-specific Hard Rules (with the why)

These are the ones that bite plugin code. The imperative versions live in AGENTS.md.

1. **Look columns up by header name, never a fixed index** — columns shift between
   batches/files. `cols = sdk.header_map(ws, header_row); col = cols.get("NEST PKG NBR")`.
2. **Scan for the header row; never hardcode it** — `sdk.find_header_row(ws, [...])`.
3. **Nest regex `^(?:[PS]?\d{3,}|(?=[A-Z0-9]*\d)[A-Z0-9]{4,8})$`** (case-insensitive) to drop
   footer/total/junk rows. Legacy numeric nests plus alphanumeric IDs like `5CDAVW`/`9FANDR`
   (first seen GX030, May 2026); requiring a digit is what rejects "TOTALS"-style junk.
4. **PyMuPDF (fitz) cannot save in place** — write a temp then replace; use
   `sdk.save_pdf_atomic(doc, dest)`.
   ```python
   import tempfile, shutil, fitz
   doc = fitz.open(pdf_path)
   # ...changes...
   with tempfile.NamedTemporaryFile(suffix='.pdf', delete=False) as tmp:
       tmp_path = tmp.name
   doc.save(tmp_path); doc.close(); shutil.move(tmp_path, pdf_path)
   ```
5. **Subprocess Unicode** — set `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8` in the env.
6. **Anything imported only inside run.py must be in `hiddenimports`** in
   `TechDeck.spec`, or the frozen exe ImportErrors at runtime (works in dev, fails built).
   Third-party: openpyxl, pandas, fitz, pypdf, qrcode+submodules, PIL+submodules, optional
   Qt submodules (e.g. `PySide6.QtCharts`). **First-party too**: `techdeck.core.plugin_sdk`
   and `techdeck.core.plugin_window` — the main app never imports them, so PyInstaller
   drops them unless listed (plugin_window's omission broke Customer DXF Quoting in the
   v0.8.6 frozen build: "Plugin validation failed ... No module named
   'techdeck.core.plugin_window'").
7. **Defensive folder resolution** (learned on `911_sspo_award_review`): real directory
   layouts vary. Resolve folders case/space-insensitively and by globbing, never by a
   hardcoded path. E.g. nest packet PDFs were specced under `WPDD SKETCHES` but actually
   live in `NEST PACKAGES` (WPDD held JPGs); the batch list was found via
   `*BATCH*LIST*.xlsx` glob, skipping `~$` lock files. Flag mismatches (a nest in the PDFs
   but not the batch list, or vice versa); don't silently drop.
8. **Poll `cancel_event` *inside* long file-system walks, not just between phases**
   (learned on LST Organizer / FormSeeker / Batch Repeater, fixed in v0.8.5.3).
   Cancellation is cooperative — the executor only sets the flag; the plugin must check
   it. A single `rglob("*")` / `os.walk` over a OneDrive batch tree can run for minutes in
   one uninterruptible call, so a Cancel mid-walk does nothing (and the run never
   completes, so the spinner spins forever) until the walk finishes on its own. Poll every
   N iterations and bail:
   ```python
   for i, p in enumerate(root.rglob("*")):
       if cancel_event is not None and i % 64 == 0 and cancel_event.is_set():
           break
       ...
   ```
   Checking between phases (`if cancel_event.is_set(): return`) is necessary but NOT
   sufficient when one phase is itself a giant walk.

## Dev-testing

- **In the app:** copy the plugin folder into `%LOCALAPPDATA%\TechDeck\plugins\<id>\` (the
  loader reads from there even in dev), then `python -m techdeck`. Re-copy `run.py` after
  edits. Remove any `__pycache__` you copy.
- **Headless (logic only, no GUI):**
  ```python
  import threading
  from plugins.my_plugin.run import run
  params = {'log': print, 'settings': {'base_path': 'C:/test/path'}, 'console': None}
  run(params, lambda p: print(f"{p}%"), threading.Event())
  ```
  For plugins that prompt, stub input: `import builtins; builtins.input = lambda *_: "..."`.
- **Frozen-build test:** `.\build.ps1` then run `dist\TechDeck\TechDeck.exe`.
- **Ship gate (run after authoring/changing any plugin):**
  `python tools\check_ship_readiness.py --load` — verifies every import will exist in
  the frozen bundle, validates manifests, GUI-thread rules, and loads each plugin like
  the app does. `build.ps1` runs this automatically and aborts the build on failure.
  Full requirements: `docs/PLUGIN_SHIP_REQUIREMENTS.md`.

## Fixing a bug? Sweep the class (AGENTS.md Fix Protocol)

Never patch only the reported site. Grep the defect pattern across `plugins/*/run.py`
AND `techdeck/core/plugin_sdk.py` (e.g. for the placeholder class:
`load_workbook\(|fitz\.open\(|PdfReader\(|read_excel\(`), fix every occurrence,
centralize in the SDK where possible, add a gate check if mechanically detectable, and
remember Hard Rule 12: copy EVERY edited plugin to `%LOCALAPPDATA%` before testing.

## Plugin failure modes

| Symptom | Cause / Fix |
|---|---|
| Plugin folder not discovered | Folder name ≠ `id`, or a double underscore. Make them match, single underscore. |
| Window vanishes instantly | GUI window stored in a local var → GC'd. Use a module-level `_window`. |
| `QBasicTimer`/crash creating widgets | Made a QWidget off the main thread. Set `requires_main_thread: true`. |
| `ModuleNotFoundError` / missing assets only in the built exe | Add the lib to `hiddenimports` / the asset dir to `datas` in `TechDeck.spec`. |
| Second same-family plugin reuses the first's batch number | Intended (family-shared). If they shouldn't share, set distinct `family`; to force a fresh prompt use `sdk.request_text`. |
| Multi-run halts with `[AUTO-PAUSE]` | A plugin sat at a prompt >60s. `/resume`, or `/shelve` then reopen. |
| Cancel does nothing during a long scan; spinner never stops | Plugin stuck in an uninterruptible `rglob`/`os.walk`. Poll `cancel_event` *inside* the walk loop (Rule 8), not just between phases. |
| Wrong Excel column / junk rows | Header lookup by name (Rules 1–2) + nest regex (Rule 3). |
| `OSError [Errno 22] Invalid argument` opening an xlsx that exists | OneDrive cloud-only placeholder; content isn't local. Use `sdk.load_workbook_resilient`; tell the user to right-click the folder → "Always keep on this device". |
| `zipfile.BadZipFile: File is not a zip file` opening an xlsx that exists (file is NOT a zip you made) | Same OneDrive placeholder failure in disguise — zipfile converts the placeholder `OSError [Errno 22]` to BadZipFile while seeking the central directory (bit 911 Setup, v0.8.6.5). `sdk.load_workbook_resilient` handles it since that fix; same user remedy as above. |
| `PermissionError: [Errno 13] Permission denied` opening/copying a workbook that exists | NOT a placeholder — the user has it OPEN in Excel (or a co-author locked it via OneDrive); the first opener's deny-share mode blocks the read, so retry/copy-to-temp can't help (bit 902 DXF Prep on the pricing `.xlsm`, v0.8.6.8). `sdk.load_workbook_resilient` / `read_excel_resilient` / `open_excel_resilient` / `copy_resilient` map it to `sdk.locked_file_error`; tell the user to close the file everywhere (and delete any stray `~$…` lock file). |
